Scope, assumptions & independent verification

Browser-local synthetic demonstration. No real agent, bank, wallet, card, payment provider or external beneficiary is connected. Candidates are scripted. Anyone controlling the browser can edit this sandbox; it is not a production security boundary.

Each comparison starts fresh isolated mock ledgers. Retries happen inside a single run; replay never debits again.

The final-gate pattern, integer-cent ledger and same-instance check-and-debit are executable here. Distributed transaction locking, durable idempotency, real identity approval and live payment integration are not implemented.

A SHA-256 checksum binds the exported bytes to the included digest; it is not a signature, trusted provenance or proof of real savings. The verifier checks against the known fixture version and recomputes outcomes—even after an attacker rehashes a changed report.

From your repository root:

python3 apps/ecai/tools/verify_payment_guard.py payment-guard.evidence.json

Local acceptance checks are not a DamageBDD backend execution. See the included operator documentation for the integration boundary and test commands.
