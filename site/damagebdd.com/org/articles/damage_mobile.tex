\section{Mobile BDD Editor}

\subsection{Interface Principles}

The editor emphasises:
\begin{itemize}
    \item Maximum ergonomic usage with a single thumb.
    \item Zero learning curve for non-technical contributors.
    \item Real-time suggestions from step libraries.
    \item Smooth fallback to raw Gherkin mode for experts.
\end{itemize}

\subsection{Features}

\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{Keyword completion:} Given / When / Then / And chips.
    \item \textbf{Step templates:} Auto-insert HTTP steps, variable steps, JSON assertions.
    \item \textbf{Smart autocompletion:} Matching pre-existing variables.
    \item \textbf{Scenario builders:} One-tap generation of common scenario structures.
    \item \textbf{Syntax highlighting:} Mobile-friendly monospaced layout with gutters.
\end{enumerate}

\subsection{Execution}

Upon running the scenario:
\begin{itemize}
    \item The client posts the feature to a DamageBDD endpoint.
    \item Real-time streaming begins (via Cowboy HTTP chunking).
    \item Each step animates on the screen (pending → active → pass/fail).
\end{itemize}

\section{On-Chain Architecture}

\subsection{Contracts}

\subsubsection{Profile Contract}

Maps:
\[
\texttt{account} \rightarrow \{handle, avatar\_cid, socials, reputation\_scores\}
\]

Provides decentralised identity linking.

\subsubsection{FeatureRuns Contract}

Each run publishes:
\[
\{\texttt{feature\_hash},\ \texttt{account},\ \texttt{status},\ \texttt{damage\_spent},\ \texttt{payout\_sats},\ \texttt{timestamp}\}
\]

This is the canonical source of truth for all verification results.

\subsubsection{Reactions Contract}

Supports:
\[
\texttt{clap},\ \texttt{comment(ipfs\_cid)},\ \texttt{fork},\ \texttt{share(platform)}
\]

\subsection{Immutable Proofs}

Everything is reconstructable from on-chain events:
\begin{itemize}
    \item Feature popularity
    \item Developer productivity
    \item Historical correctness
    \item Reputation and trust scores
    \item Challenge participation
\end{itemize}

\subsection{Economic Layer}

Powered by the \textbf{DAMAGE Token (AEX-9)}:
\begin{itemize}
    \item Verification fees
    \item Bounties
    \item Staking incentives
    \item Anti-spam economics
    \item Revenue share for the network
\end{itemize}

\section{Social Media Integration}

\subsection{On-Chain Tracking of Off-Chain Shares}

While posting to X/LinkedIn is done via native share sheets, the \emph{fact} of sharing is stored on-chain for reputation:

\[
\texttt{share(feature\_hash, account, platform)}
\]

\subsection{Comments \& Discussions}

All comments store text on IPFS and reference it via:
\[
\texttt{comment(feature\_hash, account, ipfs\_cid)}
\]

\subsection{Fork Trees}

Forking a feature creates a lineage:
\[
\texttt{fork(parent\_hash,\ child\_hash,\ account)}
\]

This creates a long-term evolutionary tree of BDD specifications for a domain.
